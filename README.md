# PC Health Agent

직원 PC(Windows 10/11)의 CPU·메모리·디스크 부족 상황과 그때 실행 중이던 프로세스를 기록합니다. 기록한 데이터로 **PC 업그레이드(RAM/SSD)나 교체가 필요한지 판정**하는 경량 에이전트입니다.

- **서버 없음:** 데이터는 PC 안에만 저장하고, 필요할 때 `export`로 zip을 만들어 전달합니다.
- **가벼움:** .NET 10 Native AOT 빌드 기준 exe 약 8MB, 메모리(작업 집합) 약 20MB, CPU 사용 전체의 0.001% 미만(시간당 약 0.4초), 디스크 기록 분당 약 150바이트입니다. (16스레드 노트북에서 기본 설정으로 3분 측정)
- **개인정보 보호:** 창 제목·문서명·URL·키 입력·화면은 수집하지 않습니다. 지정한 프로세스명은 마스킹합니다.
- **쉬운 배포:** 직원은 exe 하나를 더블클릭해 메뉴로 설치·업데이트·결과 내보내기·제거를 합니다. 이 저장소에 접근할 필요가 없습니다.

## 기능 한눈에 보기

### 1. 수집 — Windows 서비스(상시, 경량)
| 기능 | 내용 |
|---|---|
| 성능 측정 | 5초마다 CPU, 가용 메모리, 커밋, 하드 페이지 폴트, 시스템 디스크 활성·큐를 측정해 1분 단위로 저장 |
| 자원 부족 감지 | CPU 포화·메모리 부족·디스크 포화가 30초 이상 이어지면 이벤트로 기록 (진입·해제 기준을 따로 두어 순간 급증은 무시) |
| 원인 프로세스 기록 | 부족 상태가 되면 그 순간 CPU·메모리·I/O 상위 프로세스를 기록 (유형별 10분 쿨다운, 하루 최대 48회) |
| 관리자 전용 정보 | 6시간마다 부팅 시간 로그와 디스크 SMART를 기록 — 직원이 일반 권한으로 내보내도 빠지지 않음 |
| 자체 사용량 기록 | 1시간마다 에이전트 자신의 CPU·메모리 사용량을 기록 — 리포트에서 가벼움을 확인 |
| 저부하 실행 | 효율 모드(EcoQoS), 낮은 우선순위, 메모리 약 20MB, 네트워크·WMI·DB 미사용, 오래된 데이터 자동 정리(90일·200MB) |

| 기능 | 내용 |
|---|---|

| 디스크 건강(SMART) | 고장 예측, SSD 수명 사용률, 예비 공간, 미디어 오류, 재할당·불안정 섹터, 실사용 시간, 온도, 누적 기록량 |

| 안정성 기록 | Windows 이벤트 로그의 블루스크린, 비정상 종료, 앱 비정상 종료·응답 없음, 메모리 부족 경고, 부팅 시간 |
| Windows 11 호환성 | CPU 세대·TPM·UEFI·메모리·디스크 기준으로 '업그레이드 가능 / 설정 변경 후 가능 / 미지원' 판정, LTSC 구분 |
| 판정 엔진 | 고정 규칙으로 교체 권장 / 업그레이드 권장 / 점검 필요 / 양호 / 데이터 부족을 판정하고, 권장 조치마다 근거 수치를 적음 (AI 미사용) |
| 원인 프로그램 분석 | 자원 부족 때 반복해서 1위에 오른 프로그램을 찾아 증설 전에 점검할 대상을 알려 줌 |

| 기능 | 내용 |

### 4. 배포·운영
| 기능 | 내용 |
|---|---|
| 단일 실행 파일 | .NET 설치가 필요 없는 exe 하나 (Native AOT, 약 8MB) |
| 더블클릭 메뉴 | 설치·업데이트·결과 내보내기·상태 보기·제거를 숫자 키로 선택, 필요할 때만 관리자 확인 창 |
| Windows 통합 | 시작 메뉴 바로가기, 설정 > 앱 목록 등록(제거 시 데이터 삭제 여부 확인), 서비스 자동 재시작 |
| 업데이트 | 새 exe를 실행해 '업데이트'만 누르면 됨 — 수집 데이터·설정 유지 |
| 배포 패키지 | `publish.ps1`이 직원용 exe와 안내문(SHA-256 포함)을 `artifacts\dist`에 생성 — 저장소 접근 불필요 |

### 5. 개인정보·보안
외부로 아무것도 보내지 않고, 창 제목·문서 이름·웹 주소·키 입력·화면은 기록하지 않습니다. 민감한 프로세스 이름은 마스킹하고, 사용자 폴더 경로는 익명화합니다. SYSTEM 서비스를 악용한 권한 상승을 막기 위해 데이터 폴더 검증, DLL 하이재킹 방지 등을 적용했습니다. 자세한 내용은 [개인정보](#개인정보)와 [보안](#보안)을 참고하세요.

## 파일럿 진행 절차

1. **빌드:** 개발 PC에서 `.\publish.ps1`을 실행합니다. `artifacts\dist`에 배포용 파일 2개가 생깁니다.
   - `PcAgent-<버전>.exe`: 직원에게 전달할 실행 파일입니다(단일 파일, .NET 설치 불필요).
   - `설치안내-<버전>.txt`: 메신저·메일 본문에 붙여 넣을 안내문입니다(SHA-256 포함).
2. **전달:** exe와 안내문을 사내 공유 폴더·메신저·메일로 보냅니다. 방법은 [직원 배포](#직원-배포-git-없이)를 참고하세요.
3. **설치(직원):** exe를 더블클릭하고, 안내를 읽은 뒤 `1`(설치하기)을 누르고, 관리자 권한 확인 창에서 [예]를 누릅니다.
   - `C:\Program Files\PcAgent`에 복사되고 Windows 서비스 `PcAgent`로 등록됩니다. '지연된 자동 시작'이라 부팅 직후에는 부하를 주지 않습니다.
   - 시작 메뉴와 설정 > 앱 목록에 'PC Health Agent'가 생깁니다.
4. **수집:** 평소처럼 2주 이상 사용합니다. 메뉴 위쪽이나 `status`에 '수집 N일 · 판정 가능'이 표시되면 내보낼 수 있습니다.
5. **내보내기(직원):** 시작 메뉴 > PC Health Agent에서 `1`(결과 내보내기)을 누릅니다. 바탕화면에 `PcHealth_<PC명>_<시각>.zip`이 생기고 탐색기가 열리면, 이 파일을 담당자에게 보냅니다. 일반 사용자 권한으로 됩니다.
6. **취합(담당자):** zip들을 한 폴더에 모은 뒤 `PcAgent.exe merge <폴더>`를 실행합니다.
   - `fleet_summary_*.html`: 판정 분포, 조치별 대상 PC, PC별 결과를 한 장으로 보는 리포트입니다.
   - `fleet_summary_*.csv`: PC별 1행 요약(엑셀용)이며, 조치가 시급한 순(점수 높은 순)으로 정렬됩니다.
   - 에이전트 버전이 섞여 있어도 각 zip의 `summary.json`을 읽어 현재 열 구성으로 맞춥니다. 같은 PC의 zip이 여러 개면 최신 것만 씁니다.
7. **제거(직원):** 설정 > 앱 > PC Health Agent > 제거를 누릅니다(또는 시작 메뉴에서 `제거`). 수집 데이터를 지울지 묻습니다.

모든 작업은 명령줄로도 할 수 있습니다([명령어](#명령어) 참고). 관리자 권한이 필요한 명령은 권한이 없으면 확인 창을 띄웁니다.

## 직원 배포 (git 없이)

직원에게는 `artifacts\dist`의 exe 하나와 안내문만 전달합니다.

| 전달 방법 | 비고 |
|---|---|
| **사내 공유 폴더**(권장) | 공유 폴더의 exe를 바로 더블클릭해도 됩니다. 관리자 창에서는 네트워크 드라이브가 안 보일 수 있어, 로컬 임시 사본으로 설치합니다. |
| 사내 메신저·메일 | exe 첨부가 막혀 있으면 공유 폴더나 사내 드라이브 링크를 쓰세요. |
| 배포 도구(Intune·SCCM·GPO 등) | 관리자 권한으로 `PcAgent.exe install`을 실행하면 묻는 것 없이 설치됩니다. 무인 제거는 `uninstall`(데이터 유지) 또는 `uninstall --purge`입니다. |

- **"Windows의 PC 보호" 창:** 코드 서명이 없는 exe라서, 처음 실행할 때 SmartScreen이 경고합니다. [추가 정보] → [실행]으로 진행하세요. 회사에 코드 서명 인증서가 있으면 서명해 두는 것이 좋습니다.
- **관리자 권한:** 설치·업데이트·제거에는 관리자 권한이 필요합니다. 직원 계정에 관리자 권한이 없으면, IT 담당자가 확인 창에 관리자 계정을 입력하거나 배포 도구로 설치해야 합니다.
- **백신·EDR:** SYSTEM 서비스를 등록하므로, 일부 보안 제품이 확인을 요구할 수 있습니다. 필요하면 보안팀에 exe(SHA-256)를 예외로 등록해 달라고 요청하세요.
- **파일 확인:** PowerShell에서 `Get-FileHash PcAgent-<버전>.exe`를 실행한 결과가 안내문의 SHA-256과 같으면, 전달 중에 바뀌지 않은 파일입니다.

## 버전 업데이트

**개발자 — 새 버전 만들기**
1. `src/PcAgent/PcAgent.csproj`의 `<Version>`을 올립니다. 버그 수정은 `0.3.1`, 기능 추가는 `0.4.0`처럼 올립니다.
2. `dotnet test`가 통과하면 `.\publish.ps1`을 실행합니다. 새 버전 번호로 `artifacts\dist\PcAgent-<버전>.exe`와 안내문이 생깁니다.
3. 커밋하고 `git tag v<버전>`으로 태그를 붙입니다. 배포한 exe가 어떤 코드인지 추적할 수 있습니다.

**직원 — 설치된 PC 업데이트**
- 새 exe를 더블클릭하면, 설치된 버전보다 높을 때 메뉴에 `1. 업데이트`가 나옵니다. 누르고 관리자 확인 창에서 [예]를 누르면 끝납니다.
- 명령줄에서는 새 exe로 `install`을 다시 실행하면 됩니다.
- 수집 데이터와 `config.json`은 그대로 유지됩니다. 서비스를 멈추고 exe를 바꾼 뒤 다시 시작하므로, 수집은 몇 초만 멈춥니다.
- 설치된 버전은 `status`나 설정 > 앱 목록에서 확인합니다. 더 낮은 버전으로 `install`하면 경고를 띄운 뒤 그 버전으로 되돌립니다.
- 서버를 두지 않으므로 자동 업데이트는 없습니다. 새 버전은 처음과 같은 방법으로 전달합니다.

## 명령어

| 명령 | 설명 |
|---|---|
| (인자 없이 실행·더블클릭) | 메뉴: 설치·업데이트·결과 내보내기·상태·제거 |
| `install` | 설치 또는 업데이트 (관리자 권한 필요, 없으면 확인 창) |
| `uninstall [--purge]` | 제거. `--purge`면 수집 데이터도 삭제 |
| `status` | 서비스 상태·설치 버전, 수집 진행(일수·관측 시간·판정 가능 여부), 마지막 측정값, 에이전트 자체 사용량 |
| `export [--days N] [--out 폴더]` | 진단 리포트 zip 생성 (기본 30일, 바탕화면) |
| `merge <폴더> [--out 파일.csv]` | 여러 PC의 zip을 요약 CSV와 HTML 리포트로 합치기 |
| `inventory` | 하드웨어 사양 출력(JSON) |
| `version` / `menu` | 버전 출력 / cmd에서 메뉴 열기 |
| `run --data-dir <폴더>` | 서비스 없이 콘솔에서 수집 (테스트용, 서비스 데이터와 분리) |
| `--data-dir <폴더>` | 읽을 데이터 폴더 지정 (기본 `%ProgramData%\PcAgent`). install/uninstall에는 사용 불가 |

## 동작 방식

```
[Windows 서비스 PcAgent — 효율 모드, 낮은 우선순위]
  5초마다 측정 ─ CPU(GetSystemTimes), 메모리/커밋(GlobalMemoryStatusEx),
                 하드 페이지 폴트·시스템 디스크 활성/큐(PDH)
     ├─ 1분 단위로 집계 → data\metrics-YYYYMMDD.csv
     └─ 자원 부족이 30초 이상 지속되면
          → 상위 프로세스 스냅샷(CPU%·메모리·I/O) → data\pressure-YYYYMMDD.jsonl
            (유형별 10분 쿨다운, 하루 최대 48회)
  1시간마다 에이전트 자체 CPU·메모리 사용량 → agent-usage.json
  6시간마다 관리자 전용 정보(부팅 시간 로그·디스크 SMART) → privileged-cache.json

[export 실행 시에만]
  하드웨어 사양(SMBIOS·레지스트리·디스크 IOCTL·SMART·TPM·배터리) + Windows 이벤트 로그 조회
  (일반 권한이라 못 읽은 부팅 시간·SMART 는 privileged-cache.json 으로 보충)
  → 판정 엔진 → zip
```

경량화를 위해 이렇게 설계했습니다.
- **WMI, DB, 네트워크를 쓰지 않습니다.** 대신 커널 API를 직접 호출합니다.
- **사양과 이벤트 로그는 내보낼 때 조회합니다.** 일반 권한으로는 읽을 수 없는 부팅 시간 로그와 일부 디스크 SMART만 서비스가 6시간마다 기록해 둡니다(이벤트 로그 1회 조회와 디스크 조회 몇 번).
- **자원 부족 판정은 진입·해제 기준을 따로 둡니다(히스테리시스).** 순간 스파이크는 무시하고, 상태가 경계값 근처에서 오르내려도 이벤트가 폭주하지 않습니다.
- **에이전트 자신의 우선순위를 낮춥니다.** CPU 우선순위 '낮음', 효율 모드(EcoQoS), 메모리 우선순위 '낮음'으로 실행됩니다.
- **로컬 데이터는 자동으로 정리합니다.** 보존 기간 90일, 용량 상한 200MB를 넘으면 오래된 것부터 지웁니다.

## 개인정보

- **수집하는 것:** 프로세스 이름, 실행 파일 경로, 게시자, CPU/메모리/I/O 사용량, 시스템 지표, 하드웨어 사양(디스크 SMART, 배터리 용량·충전 횟수 포함), 안정성 이벤트
- **수집하지 않는 것:** 창 제목, 문서·파일 이름, 웹 주소, 키 입력, 화면, 명령줄 인수
- **경로:** `C:\Users\홍길동\...`처럼 사용자 계정이 드러나는 부분은 항상 `%USERPROFILE%\...`로 바꿔 저장합니다.
- **마스킹:** `maskProcessPatterns`에 맞는 프로세스는 `[masked-xxxxxx]`로 저장하고, 경로와 게시자는 지웁니다.
  - PC 고유값으로 해시하므로 내보낸 파일만으로는 원래 이름을 알 수 없습니다. 다만 그 PC에 접근할 수 있는 사람은 흔한 프로그램 이름을 대입해 추측할 수 있습니다.
  - 설정을 바꾸면 이미 저장된 데이터에도 내보낼 때 적용됩니다.
- **데이터 폴더 권한:** SYSTEM과 관리자만 쓸 수 있고, 일반 사용자는 읽기만 됩니다. 본인 PC 데이터를 직접 확인하고 내보낼 수 있습니다. 여러 사람이 함께 쓰는 PC라면 다른 사용자의 프로세스 목록도 읽을 수 있다는 점에 유의하세요.

## 보안

SYSTEM 권한으로 도는 서비스라, 일반 사용자가 이를 이용해 관리자 권한을 얻지 못하도록 다음을 적용했습니다.

- **네트워크 통신 없음:** 열어 두는 포트도, 외부로 보내는 데이터도 없습니다.
- **데이터 폴더 검증:** 서비스는 시작할 때마다 데이터 폴더를 검사합니다.
  - 링크(junction/symlink)가 아니고, 소유자가 SYSTEM/Administrators이며, 다른 계정에 쓰기 권한이 없어야 합니다.
  - 조건을 만족하지 않으면 수집하지 않고, 이벤트 뷰어(Windows 로그 > 응용 프로그램, 원본 `PcAgent`)에 이유를 남깁니다.
  - `install`은 일반 사용자가 미리 만들어 둔 폴더를 치우고, 생성과 동시에 권한을 적용해 다시 만듭니다.
- **DLL·실행 파일 하이재킹 방지:** exe를 다운로드 폴더 등에서 관리자 권한으로 실행해도, 같은 폴더에 심어 둔 가짜 DLL이나 `sc.exe`가 실행되지 않습니다. 필요한 DLL과 도구는 System32에서만 불러옵니다(AOT 빌드의 `/DEPENDENTLOADFLAG`, P/Invoke 검색 경로 제한). AOT가 아닌 대체 빌드에는 `/DEPENDENTLOADFLAG`가 적용되지 않으므로, 그 경우 exe를 일반 사용자가 쓸 수 없는 폴더에 두고 설치하세요.
- **네트워크 경로 접근 안 함:** `\\서버\...`에서 실행된 프로그램은 게시자 정보를 읽지 않습니다. SYSTEM이 원격 파일을 열면 PC 계정 인증이 원격 서버로 전달되어 NTLM 릴레이 공격에 악용될 수 있기 때문입니다.
- **경로 고정:** install/uninstall과 서비스는 항상 기본 경로만 쓰며 `--data-dir`을 받지 않습니다.
- **자기 삭제 스크립트 없음:** 실행 중인 exe는 지울 수 없어서, 제거할 때 임시 폴더로 옮긴 뒤 재부팅 때 지우도록 예약합니다. cmd로 자기 자신을 지우는 방식은 백신이 악성 패턴으로 볼 수 있어 쓰지 않습니다.
- **관리자 권한 재실행:** 권한이 필요한 명령은 같은 exe를 UAC 확인 창으로 다시 실행합니다. 다운로드 보안 경고는 사용자가 이미 실행을 허락한 같은 파일이라 한 번만 뜨게 했습니다.
- **남은 권장 사항:** 사내 배포 전에 exe에 코드 서명을 하세요.

## 판정 기준 (`UpgradeAdvisor`)

업무시간(평일 9~18시) 데이터가 8시간 이상이면 업무시간 기준으로, 그보다 적으면 전체 시간 기준으로 판정합니다. 성능 기반 판정(프로그램 점검 포함)에는 8시간 이상의 관측이 필요합니다.

| 조건 | 권장 조치 |
|---|---|
| 메모리 부족 비율 ≥ 5% (또는 Windows 메모리 부족 경고 2회 이상, 또는 RAM ≤ 4GB) | **메모리 증설** (목표 용량, 빈 슬롯 안내). 온보드 메모리면 **PC 교체** |
| 메모리 부족 비율 2~5% | 메모리 사용 관찰 |
| 프로세스 기록이 있는 메모리 부족 이벤트의 60% 이상에서 같은 프로그램이 1위 | 해당 **프로그램 점검**. 이때 메모리 증설·교체 권고는 '보통'으로 낮추고 프로그램을 먼저 확인하게 함 (RAM 4GB 이하는 제외) |
| 시스템 디스크가 HDD | **SSD 교체** (디스크 포화 3% 이상이면 우선순위 높음) |
| 디스크 고장 예측(SMART), NVMe 치명 경고, SSD 수명 100% 이상, 불안정·복구 불가 섹터 | **디스크 교체** (높음). 시스템 디스크가 HDD면 SSD 교체로 합침 |
| SSD 수명 80% 이상, 재할당 섹터, 미디어 오류 | 디스크 점검 (백업 확인, 추이 관찰) |
| CPU 포화 비율 ≥ 10% + (추정 연식 5년 이상, 구형 CPU, 2코어 이하 중 하나) | **PC 교체** |
| CPU 포화 비율 ≥ 10% (위 조건 해당 없음) | CPU 사용 검토 / 프로그램 점검 |
| Windows 10 + 하드웨어가 Windows 11 요구사항 미충족 (CPU 세대, TPM 1.2, 메모리·디스크 용량) | **PC 교체** |
| Windows 10 + 요구사항 충족 | Windows 11 업그레이드 |
| Windows 10 + 레거시 BIOS 부팅 또는 TPM 꺼짐 (설정 문제) | Windows 11 업그레이드 (UEFI 전환·TPM 활성화 먼저) |
| Windows 10 LTSC/IoT 에디션 | 지원 주기가 달라 Windows 11 전환을 권고하지 않음 |
| 블루스크린 2회 이상 / 비정상 종료 3회 이상 | 안정성 점검 |
| 시스템 드라이브 여유 공간 < 10% 또는 < 10GB | 디스크 공간 확보 |
| 노트북 배터리 수명(완충 ÷ 설계 용량) ≤ 40% / ≤ 60% | **배터리 교체** (높음) / 배터리 교체 검토 (보통). 80% 이하는 참고로만 표시 |

판정 결과는 교체 권장 / 업그레이드 권장 / 점검 필요 / 양호 / 데이터 부족 중 하나입니다. 조치 점수는 '높음' 40점, '보통' 15점으로 계산하고 최대 100점입니다. 임계값은 파일럿 결과를 보고 `src/PcAgent/Analysis/UpgradeAdvisor.cs`에서 조정하세요.

> Windows 11 CPU 지원 여부는 모델명 기반 추정입니다(Intel 8세대 이상, AMD Ryzen 2000 이상). 최종 확인은 'PC 상태 검사' 앱으로 하세요. 추정 연식은 BIOS 날짜 기준이라, BIOS를 업데이트했다면 실제보다 짧게 나옵니다.

## 설정 (`%ProgramData%\PcAgent\config.json`)

설치할 때 기본값으로 생성됩니다. 파일을 수정하면 5분 안에 서비스 재시작 없이 반영됩니다. 주요 항목은 아래와 같습니다.

```jsonc
{
  "sampleIntervalSeconds": 5,          // 측정 주기
  "retentionDays": 90,                 // 보존 기간
  "maxDataSizeMb": 200,                // 용량 상한
  "cpuHighPercent": 90, "cpuRecoverPercent": 70, "cpuSustainSeconds": 30,
  "memoryAvailableLowPercent": 10,     // 가용 메모리 ≤ 10% 또는
  "commitHighPercent": 90,             // 커밋 ≥ 90% → 메모리 부족
  "diskActiveHighPercent": 90,
  "topProcessCount": 8,                // 스냅샷 시 CPU/메모리/I/O 각 상위 N개
  "snapshotCooldownMinutes": 10, "maxSnapshotsPerDay": 48,
  "includeProcessPaths": true,         // false 면 경로 미저장
  "maskProcessPatterns": ["KakaoTalk*", "Telegram*", "Discord*", "Steam*", "*torrent*"],
  "workStartHour": 9, "workEndHour": 18, "workdaysOnly": true
}
```

## 개발

```powershell
dotnet build
dotnet test                                    # 단위 테스트
dotnet run --project src/PcAgent -- inventory  # 사양 확인
dotnet run --project src/PcAgent -- run --data-dir .\devdata
.\publish.ps1                                  # 배포용 단일 exe + artifacts\dist (직원 배포 패키지)
```

- **구조:** `Collection`(측정·감지), `Storage`(파일 저장), `Inventory`(사양), `EventLogs`, `Analysis`(판정), `Export`(리포트), `Hosting`(서비스·설치)
- **.NET 버전:** .NET 10 LTS(지원 종료 2028-11-14)를 씁니다. 빌드하려면 .NET 10 SDK가 필요하며, `global.json`이 10.0.x SDK로 고정합니다. 버전을 바꿀 때는 `Directory.Build.props`의 `NetVersion`, `global.json`, 패키지 버전을 함께 바꿉니다.
- **Native AOT:** 빌드 PC에 Visual Studio의 'C++를 사용한 데스크톱 개발'이 있으면 `publish.ps1`이 자동으로 AOT 빌드합니다. 코드는 AOT 호환이며, 빌드 시 AOT/트리밍 분석 경고가 0건입니다.
- **배포 보안:** 서비스가 SYSTEM 권한으로 실행되므로, 사내 배포 전에 코드 서명을 권장합니다. 백신·EDR이 오탐하면 보안팀에 예외 등록을 요청하세요.
